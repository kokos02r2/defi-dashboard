# Выкладка на свой Mac mini

Тот же подход, что в [DEPLOY.md](../DEPLOY.md), только под macOS:
**launchd вместо systemd** и **Caddy вместо nginx+certbot**. Docker не нужен —
приложение однопроцессное с SQLite внутри.

| Роль | На Linux-сервере | Здесь |
|---|---|---|
| держать процесс живым | systemd | launchd (LaunchDaemon) |
| HTTPS наружу | nginx + certbot | Caddy (сертификат сам, сам продлевает) |
| проверка домена | HTTP-01, порт 80 | **DNS-01 через API DuckDNS** — порты не нужны |
| внешний порт | 443 | **8443** — роутер не отдаёт 443 |
| имя в интернете | DuckDNS | DuckDNS + обновлятор раз в 5 минут |
| доступ из дома | тот же адрес | **второе имя** — роутер без NAT hairpinning |
| бэкап базы | cron.daily | launchd, 04:20 |

Адреса — два, каждый для своего случая:

| Откуда | Адрес |
|---|---|
| извне (мобильный интернет, работа, поездка) | `https://ПОДДОМЕН.duckdns.org:8443` |
| из своей Wi-Fi сети | `https://ПОДДОМЕН-lan.duckdns.org:8443` |

---

## Статический IP не нужен

Это главный вопрос, и ответ на него — нет.

**Динамический адрес** решается DuckDNS: раз в 5 минут скрипт дёргает
`duckdns.org/update`, и DNS-запись показывает на текущий адрес. Провайдер сменил
IP — имя догоняет его за пару минут. Именно для этого DuckDNS и существует.

Что **действительно** нужно:

1. **Фиксированный локальный адрес мака** (сейчас `192.168.0.23`) — не «статика»
   от провайдера, а настройка внутри вашей сети, бесплатно. Иначе проброс портов
   однажды укажет на телевизор.
2. **Проброс одного порта — 8443** — на этот мак.
3. **Реальный публичный IP от провайдера**, а не CGNAT. Проверка ниже.

Порт 80 в этой схеме не нужен вообще: сертификат выпускается DNS-проверкой,
о ней ниже.

### Почему 8443, а не 443

Роутер Vodafone (и вообще большинство операторских роутеров) держит внешние
**80 и 443** под свой веб-интерфейс и на попытку их пробросить отвечает
«*The selected port cannot be configured as it is reserved for internal usage*».
Ни настройками, ни DMZ это не обходится.

Отсюда два следствия:

- дашборд живёт на внешнем порту **8443**, и его надо писать в адресе явно;
- обычная проверка Let's Encrypt (HTTP-01) не годится — ей нужен входящий 80.
  Вместо неё используется **DNS-01**: Caddy сам кладёт TXT-запись через API
  DuckDNS, и входящие порты для выпуска сертификата не требуются совсем.
  Сертификат при этом настоящий, браузер ничего не спрашивает.

Для DNS-01 нужен `caddy` с модулем `dns.providers.duckdns` — в сборке из
Homebrew его нет, поэтому `setup.sh` кладёт рядом `caddy-duckdns` (официальная
сборка с caddyserver.com, скачивается один раз).

### Как понять, что провайдер не отдаёт публичный адрес (CGNAT)

```bash
curl -s https://api.ipify.org        # что видит интернет
```

Зайдите в роутер, Status & Support → и посмотрите его **WAN IPv4 Address**.
**Совпадает** — проброс заработает. **Не совпадает** (особенно если у роутера
адрес из `100.64.x.x`, `10.x.x.x`, `172.16–31.x.x`) — вы за CGNAT, входящие
соединения до вас не доходят, и никакой DuckDNS этого не изменит. Тогда:

- попросить у провайдера публичный IP (часто дают бесплатно или за копейки);
- либо пустить трафик через туннель — см. «Если порты не открыть» в конце.

## 1. Домены в DuckDNS

1. [duckdns.org](https://www.duckdns.org), вход через GitHub.
2. Придумайте поддомен, например `kokos-defi`, → **add domain**.
   Поле **current ip** заполнять не нужно, это сделает обновлятор.
3. Заведите второй, с тем же именем и суффиксом `-lan`: `kokos-defi-lan`.
   Он будет показывать на локальный адрес мака — зачем, объяснено в разделе
   «Из своей Wi-Fi сети». Адрес ему тоже поставит обновлятор.
4. Скопируйте **token** с верха страницы. Он один на все домены аккаунта и
   используется ещё и для выпуска сертификатов.

## 2. Установка

Один раз, из каталога проекта:

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt

sudo ./deploy/mac/setup.sh ПОДДОМЕН TOKEN ваша@почта
```

Скрипт: правит `.env` под HTTPS, скачивает `caddy-duckdns` (если нет), собирает
Caddyfile, ставит четыре службы launchd (приложение, Caddy, обновлятор DuckDNS,
ежедневный бэкап), разрешает Caddy в файрволе macOS, запрещает маку засыпать,
включает автозапуск после сбоя питания и проверяет, что и приложение, и HTTPS
ответили. Запускать повторно можно сколько угодно — данные не трогаются.

> Python **3.12**, не 3.13+: в новых версиях выпилен модуль `crypt`, на котором
> падает `passlib` — библиотека хеширования пароля.

Ни один из процессов не требует root: порты 8443 и 8787 выше 1024. Root нужен
только самому `setup.sh` — чтобы положить службы в `/Library/LaunchDaemons`,
откуда они стартуют при загрузке машины, ещё до входа в систему.

## 3. Сеть

Сначала закрепите за маком локальный адрес — иначе проброс однажды укажет на
другое устройство. Надёжнее прописать адрес **вручную на самом маке**:
Настройки → Сеть → Wi-Fi → Подробнее → TCP/IP → Конфигурация IPv4 «Вручную»,
адрес `192.168.0.23`, маска `255.255.255.0`, роутер `192.168.0.1`.

Так это не зависит ни от DHCP, ни от MAC-адреса — а у Wi-Fi на macOS MAC
«приватный» и меняется сам, из-за чего привязка на роутере по MAC со временем
разваливается. Адрес стоит взять за пределами пула DHCP роутера (обычно пул
`.100–.199`), либо оставить `.23`, если пул начинается выше.

Дальше роутер (`http://192.168.0.1`) → **Internet** → **Port Mapping** → «+»:

| Поле | Значение |
|---|---|
| Service | TCP |
| Device | No specific device |
| LAN IP | `192.168.0.23` |
| Type | Port |
| Public Port | `8443` |
| LAN Port | `8443` |

**Apply**. Одного правила достаточно.

Не используйте **DMZ** — он выставит мак в интернет целиком, всеми портами.
**Port Triggering** — не то, это про порты, открывающиеся в ответ на исходящий
трафик. **NAT Traversal** (UPnP) оставьте как есть, правило мы завели руками.
Раздел **DNS & DDNS** тоже не нужен: DuckDNS обновляет служба на маке.

## 4. Проверка

```bash
dig +short ПОДДОМЕН.duckdns.org     # должен отдать ваш публичный IP
```

Дальше откройте `https://ПОДДОМЕН.duckdns.org:8443` **с телефона по мобильному
интернету**, а не из домашнего Wi-Fi: многие роутеры не умеют разворачивать
запрос к собственному внешнему адресу изнутри сети (NAT hairpinning), и «не
открывается из дома» ещё ничего не значит.

Порт снаружи: [yougetsignal.com/tools/open-ports](https://www.yougetsignal.com/tools/open-ports/)
— вбейте 8443.

Первый заход — форма входа. Логин и пароль — из `.env` (`ADMIN_USERNAME`,
`ADMIN_PASSWORD`), они применяются один раз, при создании пустой базы.

> По `http://127.0.0.1:8787` войти уже не получится: с `SESSION_HTTPS_ONLY=true`
> кука сессии по открытому HTTP не ставится. Это не поломка, так и задумано —
> входите по внешнему адресу.

## 5. Из своей Wi-Fi сети

Внешний адрес из дома не открывается, и это тоже роутер: он не разворачивает
запрос к собственному внешнему адресу обратно в локальную сеть (нет **NAT
hairpinning**). Настройками не лечится.

Поэтому второй поддомен `ПОДДОМЕН-lan.duckdns.org` показывает прямо на локальный
адрес мака — DuckDNS не запрещает держать в записи частный адрес. Дома запрос
идёт к маку напрямую, минуя роутер:

```
https://ПОДДОМЕН-lan.duckdns.org:8443
```

Сертификат Caddy получает и на это имя (той же DNS-проверкой), поэтому браузер
ничего не спрашивает — в отличие от захода по `https://192.168.0.23:8443`, где
имя в сертификате не совпадёт с адресом.

Снаружи это имя не работает вовсе: там частный адрес, идти по нему некуда. Так и
задумано — снаружи основное имя, дома `-lan`.

Обновлятор переставляет и эту запись каждые 5 минут на текущий локальный адрес,
так что смена адреса мака домашний доступ не ломает.

Одна возможная помеха: некоторые роутеры вырезают частные адреса из DNS-ответов
(защита от DNS rebinding). Проверить, что ваш так не делает:

```bash
dig +short 192-168-0-23.nip.io @192.168.0.1     # должен ответить 192.168.0.23
```

Пусто в ответ — режет; тогда прописать на устройстве DNS `1.1.1.1` вручную.

## Перенести базу, если история уже есть на другой машине

Иначе на маке начнётся с нуля: кошельки, партии, настройки и график капитала
останутся там. **На старой машине**, остановив приложение:

```bash
.venv/bin/python -c "
import sqlite3
s=sqlite3.connect('data/dashboard.sqlite3'); d=sqlite3.connect('/tmp/dashboard.sqlite3')
s.backup(d); d.close(); s.close()"
```

`.backup()`, а не `cp` — копия согласована даже при активном WAL. Перенесите
файл на мак и:

```bash
sudo launchctl bootout system/com.kokos.defi-dashboard
cp /путь/dashboard.sqlite3 data/dashboard.sqlite3
rm -f data/dashboard.sqlite3-wal data/dashboard.sqlite3-shm
sudo launchctl bootstrap system /Library/LaunchDaemons/com.kokos.defi-dashboard.plist
```

Пароль останется тот, что был в старой базе.

```bash
cd "/Users/konstantinkosolapov/Сервер defi/defi-dashboard"

# логи
tail -f data/logs/dashboard.log
tail -f data/logs/caddy.log           # сертификат, входящие запросы

# службы

sudo launchctl kickstart -k system/com.kokos.caddy
launchctl print system/com.kokos.defi-dashboard | head -20     # состояние

# приложение
.venv/bin/python manage.py stats
.venv/bin/python manage.py passwd kokos      # сменить пароль
.venv/bin/python manage.py refresh sync      # полная синхронизация вручную
.venv/bin/python manage.py notify-test       # проверить Telegram

# бэкапы
ls -la backups/                              # каждые сутки, хранятся 14 дней
./deploy/mac/backup.sh                       # разово
```

Копии стоит иногда уносить с мака — на диске рядом с оригиналом они не спасают
от смерти диска.

### Проверить сертификат

```bash
echo | openssl s_client -connect 127.0.0.1:8443 \
  -servername ПОДДОМЕН.duckdns.org 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates
```

Продлевает Caddy сам, за 30 дней до конца, той же DNS-проверкой. Ничего
настраивать не нужно, но если в `caddy.log` появятся ошибки продления — первым
делом проверьте, что token DuckDNS ещё живой.

### Обновить код

Автодеплой из GitHub Actions (раздел 8 в DEPLOY.md) тут не годится: у мака нет
постоянного публичного ssh. Обновление вручную:

```bash
git pull
.venv/bin/pip install -q --upgrade -r requirements.txt
sudo launchctl kickstart -k system/com.kokos.defi-dashboard
```

### Снять всё

```bash
for s in defi-dashboard caddy duckdns defi-dashboard-backup; do
  sudo launchctl bootout "system/com.kokos.$s" 2>/dev/null
  sudo rm -f "/Library/LaunchDaemons/com.kokos.$s.plist"
done
```

## Про безопасность на домашней машине

Дашборд **только читает** блокчейн: знает публичные адреса кошельков, ничего не
подписывает, приватных ключей у него нет. Худшее от взлома входа — чужой человек
видит ваши позиции.

Уже сделано:

- пароль хранится хешем argon2;
- вход ограничен: 8 попыток за 5 минут с одного IP (реальный IP приложение видит
  из `X-Forwarded-For` от Caddy благодаря `--proxy-headers`);
- `SESSION_HTTPS_ONLY=true` — кука сессии не уходит по открытому HTTP;
- приложение слушает только `127.0.0.1`: даже в домашней сети порт 8787 напрямую
  не открыт, наружу смотрит один Caddy;
- наружу открыт ровно один порт, 8443, и ведёт он только в Caddy;
- ни приложение, ни Caddy не работают от root.

В файлах лежат два секрета, у обоих права 600: `.env` (пароль входа, токен
Telegram) и `Caddyfile` вместе с `deploy/mac/duckdns.sh` (token DuckDNS).
Последние два в `.gitignore` — в репозиторий не уедут.

Отличие от арендованного сервера, о котором стоит знать: **проброшенный порт —
это дверь в вашу домашнюю сеть**. Поэтому:

- не пробрасывайте больше ничего, особенно 22 (ssh) и 5900 (Screen Sharing);
- держите macOS обновлённой и включите файрвол:
  Системные настройки → Сеть → Файрвол;
- пароль от дашборда — длинный и нигде больше не использованный.

Нестандартный порт 8443 сам по себе немного помогает: массовые сканеры чаще
ходят по 443. Но это не защита, а шум — защита именно в пароле.

Если хочется строже: в Caddyfile можно пустить только свои адреса, или добавить
TOTP в приложение — скажите, сделаю.

## Если порты не открыть

Провайдер за CGNAT или режет всё входящее — тогда публичного адреса на домене
DuckDNS не будет, как бы ни настраивать роутер. Рабочая замена, не требующая ни
портов, ни публичного IP:

- **Tailscale Funnel** — даёт свой публичный HTTPS-адрес вида
  `mac-mini.xxxx.ts.net`, бесплатно, сертификат настоящий, порт обычный 443.
  Домен будет не duckdns, зато без `:8443` в адресе.
- **Tailscale без Funnel** — доступ только со своих устройств, где стоит клиент.
  Самый закрытый вариант: наружу вообще ничего не смотрит.
- **Cloudflare Tunnel** — то же самое, но нужен свой домен в Cloudflare
  (`duckdns.org` туда не завести).

Приложение и launchd при этом остаются те же, меняется только то, что стоит
перед ними.
